# RoleFit Canvas

> 지원할 회사의 공고와 나의 이력을 연결해, **무엇을 보여주고 무엇을 더 준비할지** 알려주는 웹앱.

「RoleFit Canvas 앱 기획서 v4.0」(MindCanvas, 2026.09.11)의 구현체입니다.
하나의 지원 건에서 서로 다른 독자를 가진 **두 결과물**을 함께 만듭니다.

| | 결과물 01 · 기업 제출용 | 결과물 02 · 지원자 전용 |
|---|---|---|
| 무엇 | 맞춤형 Resume / CV | 지원전략 분석서 |
| 답하는 질문 | "나를 어떻게 보여줄 것인가" | "어디가 맞고 무엇을 더 준비할 것인가" |
| 공개 범위 | 사용자 확인 후 제출 | 기본 비공개 |

---

## 분석 파이프라인

```
JD 분석                내 이력 분석
(인재상 + requirements)  (경력·학위·프로젝트·활동)
      │                      │
      └──────────┬───────────┘
                 ▼
   ① 직접 매핑 (baseline)      →  현재 매칭률      →  이력서 1 · Baseline
                 ▼
   ② 스토리텔링 매핑 (최대치)    →  스토리텔링 후     →  이력서 2 · 제출용  ★
                 ▼
   ③ 개선 과제 + 목표          →  목표 매칭률      →  이력서 3 · 미래(계획)
```

매칭 3단계와 이력서 3판본이 **1:1로 대응**합니다. 같은 근거로 점수가 매겨지고 같은 근거로 문장이 쓰입니다.

### 세 판본의 차이

| 판본 | 담는 내용 | 제출 |
|---|---|---|
| **1 · Baseline** | 직접 수행한 사실만. 모든 문장이 직접 근거를 가짐 | 가능 |
| **2 · 제출용** ★ | 이미 가진 관련 경험까지 이 직무와 연결해 설명 | **기본 제출본** |
| **3 · 미래(계획)** | 실행 과제를 완료했을 때의 모습. `[예정]` 표시 | **불가** |

> 이력서 3은 지원자 전용 계획 미리보기입니다. 아직 사실이 아닌 항목이 들어 있어 제출용으로 내려받을 수
> 없습니다. 기획서 06의 "예정된 학위·자격·교육·프로젝트는 완료된 이력서 항목으로 넣지 않는다"를 코드로
> 강제한 것입니다.

## 설계에 못박은 원칙

기획서의 서술 원칙을 주석이 아니라 **타입과 테스트로** 강제했습니다.

| 원칙 | 어디서 강제되는가 |
|---|---|
| 수치는 합격확률이 아니라 **직무 매칭률** | 화면 용어 통일, `READING_NOTE`를 결과 화면마다 고정 |
| 근거 없는 내용은 만들지 않는다 | 모든 점수·문장이 `EvidenceRef`를 참조. 없으면 `needs-confirmation` |
| 사실과 앱의 해석을 구분한다 | `RationaleNote`가 `evidence`(원문 인용)와 `interpretation`(해석)을 분리 |
| **문장만 고쳐도 점수가 오르지 않는다** | `afterStory`는 실제 관련 경험이 있을 때만 상승 |
| **체크만으로 목표 점수를 주지 않는다** | `reassess()`가 `evidence-submitted` + 증거 설명이 있는 과제만 반영 |
| 총점과 필수 조건은 다른 정보 | `MustHaveStatus`를 총점과 별도로 계산·표시 |
| 학력·수료를 실무 연수로 바꾸지 않는다 | 경력연수 부문은 `target`에 미래 개월을 더하지 않음 (`targetCaveat`) |
| 분석서를 이력서에 자동 포함하지 않는다 | 두 문서가 별도 빌더·별도 파일로 분리 |

기획서 03의 검증 수치(**32.75 → 45.25 → 71.50**, 화면 **33 → 45 → 72**)는 회귀 테스트로 고정되어
있습니다 — `src/lib/__tests__/scoring.test.ts`.

## 시작하기

```bash
npm install
npm run dev        # http://localhost:3000
```

키 없이 바로 동작합니다. 규칙 기반 분석 엔진이 기본입니다.
정밀 분석을 켜려면 `.env.local`에 `ANTHROPIC_API_KEY`를 넣으세요 (`.env.example` 참고).
키가 없으면 앱은 조용히 규칙 기반으로 계속 동작합니다.

```bash
npm run build      # 프로덕션 빌드
npm test           # 테스트
npm run lint
```

## 구조

```
src/
├─ lib/
│  ├─ types.ts          도메인 모델 — 유일한 진실
│  ├─ scoring.ts        가중 매칭률, 재평가, 지원 판단
│  ├─ templates.ts      기본 템플릿 5종
│  ├─ engine/           JD 분석 · 이력 분석 · 매핑 · 3판본 이력서 생성
│  ├─ export/           Word · 텍스트 · 인쇄(PDF) 내보내기
│  └─ samples/          데모 샘플 A~E
├─ store/               지원 건 상태 (localStorage 보관)
├─ components/          화면과 UI 프리미티브
└─ app/                 라우트 · API
```

## 이 앱이 하지 않는 것

- 합격 확률을 예측하지 않습니다.
- 없는 경험을 만들어 넣지 않습니다.
- 대량 자동 지원이나 채용팀의 자동 후보 선별을 하지 않습니다.
- 직무와 무관한 나이·성별·외모·종교·가족관계로 인재상이나 점수를 만들지 않습니다.
- 낮은 점수로 불안을 자극하거나, 결제로 점수를 올리지 않습니다.

샘플의 회사·인물·수치는 모두 가상입니다.
